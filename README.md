# Джарвис — личный локальный ИИ-ассистент

Чат-ассистент, который работает **целиком на вашем компьютере** через [Ollama](https://ollama.com).
Данные никуда не отправляются.

> Проект в разработке. Готово: **этап 1** — чат со стримингом, история диалогов,
> выбор модели, «размышления» Qwen3, индикатор видеопамяти; **этап 2** — настройки
> в интерфейсе, персоны (учитель, программист, редактор и свои), параметры генерации,
> размер контекста с оценкой видеопамяти; **этап 3** — долговременная память: ассистент
> запоминает факты о вас, подставляет подходящие в ответы, страница «Память» с правкой и отменой;
> **этап 4** — база знаний: PDF, DOCX, TXT, MD и папка Obsidian, ответы со ссылками на источники.
> Полная инструкция появится на этапе 8.

## Что нужно

- Windows 10/11 (Linux/macOS тоже работают)
- Видеокарта NVIDIA с 8 ГБ памяти (проверено под RTX 2060 Super)
- [Ollama](https://ollama.com/download)
- [Python 3.12](https://www.python.org/downloads/) (при установке отметьте «Add python.exe to PATH»)

## Быстрый старт (Windows)

1. Скачайте модели (один раз, ~5 ГБ):
   ```bat
   ollama pull qwen3:8b
   ollama pull llama3.1:8b
   ```
   Вторая модель нужна только для сравнения, её можно пропустить.
2. Дважды кликните по `start.bat`. Он создаст окружение, установит пакеты и откроет
   интерфейс по адресу http://127.0.0.1:8000.

Вручную (любая ОС):
```bash
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python -m backend --open
```

## Настройки

Почти всё настраивается в интерфейсе (шестерёнка внизу слева):
- **Основное** — имя ассистента, системный промпт, модель и персона по умолчанию,
  размер контекста с оценкой видеопамяти, сжатие KV-кэша.
- **Персоны** — роли с собственной инструкцией и параметрами генерации
  (температура, top-p, top-k, штраф за повторы, длина ответа). Встроенные можно
  менять и сбрасывать, свои — создавать и удалять. Персона выбирается в верхней панели.

## Память

Джарвис сам замечает в разговоре факты о вас («Учусь на 2 курсе», «Пишу на JavaScript»)
и под ответом пишет «💾 Запомнил: … · Отменить». Подходящие факты подставляются в
следующие ответы — под ответом видно «🧠 3 факта» (наведите, чтобы увидеть какие).
Пароли, номера карт и телефонов не сохраняются никогда.

На странице **«Память»** (кнопка в боковой панели) факты можно искать, править,
закреплять 📌 (подставляются всегда), удалять и добавлять вручную; любое изменение
отменяется через журнал. Там же — выключатели памяти и автозапоминания.

Когда фактов станет много, выбираются подходящие к вопросу по смыслу — для этого
скачайте модель эмбеддингов (она работает на процессоре и не занимает видеопамять):
```bat
ollama pull bge-m3
```
Без неё подбор идёт по совпадению слов.

## База знаний

Страница **«База знаний»** (кнопка в боковой панели):
- **Загрузить файлы** — PDF, DOCX, TXT, MD (перетащите в окно). Файлы раскладываются по коллекциям
  («Мои файлы», «Алгоритмы»…).
- **Подключить папку** — например, хранилище Obsidian (`C:\Users\имя\Documents\Obsidian Vault`).
  Заметки читаются прямо из папки; после правок нажмите «Синхронизировать» — новые, изменённые
  и удалённые заметки подхватятся сами. Служебная папка `.obsidian` пропускается.
- **Проверить поиск** — увидеть, какие фрагменты найдутся по вопросу.

В чате над полем ввода выберите, где искать: во всей базе, в одной коллекции или нигде.
Ответ содержит ссылки **[1]**, **[2]** — по клику открывается фрагмент, а PDF — сразу на нужной странице.

Поиск гибридный: по смыслу (модель `bge-m3`, работает на процессоре) и по словам (полнотекстовый
индекс SQLite). Без `bge-m3` работает только поиск по словам. Индексация на процессоре —
примерно 0,2–0,5 с на фрагмент (учебник на 300 страниц — несколько минут, в фоне).
Сканы PDF без текстового слоя не поддерживаются (нужно OCR).

Файл `.env` (скопируйте из `.env.example`) нужен для того, что задаётся до запуска:
адрес Ollama, порт, движок. Значения `ASSISTANT_NAME`, `DEFAULT_MODEL`, `NUM_CTX` служат
начальными — после изменения в интерфейсе действуют настройки из интерфейса.

Переход на llama.cpp вместо Ollama: `LLM_BACKEND=llamacpp` и запущенный
`llama-server -m модель.gguf -c 8192 -ngl 99 --jinja --port 8080`.

## Структура

```
backend/
  main.py          сборка приложения FastAPI
  config.py        настройки из переменных окружения / .env
  db.py            SQLite и миграции схемы
  llm/             адаптеры движков: Ollama, llama.cpp (общий интерфейс base.py)
  chat/            диалоги: хранение, сборка контекста и системного промпта, API со стримингом
  settings/        настройки, персоны, оценка видеопамяти
  memory/          долговременная память: хранение, выбор фактов, извлечение из диалога
  knowledge/       база знаний: разбор файлов, нарезка, индексация, гибридный поиск
  system/          здоровье Ollama, список моделей, состояние VRAM
frontend/          интерфейс на чистом HTML/CSS/JS, библиотеки в vendor/ (без CDN)
tests/             тесты и эмулятор Ollama (работают без видеокарты)
data/              ваша база диалогов, копии загруженных файлов (не попадает в git)
```

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тестам не нужны ни Ollama, ни видеокарта: они используют эмулятор `tests/fake_ollama.py`.
Его можно запустить и отдельно, чтобы поработать с интерфейсом без модели:
`python -m uvicorn tests.fake_ollama:app --port 11434`.
